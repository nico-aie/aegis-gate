| [`BUG-console-route-mutation-not-fleet-convergent.md`](./BUG-console-route-mutation-not-fleet-convergent.md) | BUG (config-plane / cluster convergence) | 🔴 HIGH | 🔴 **Open.** Console route add/edit/delete (`PUT`/`DELETE /api/routes/{id}`) applies **only on the node that handled the request** — not fleet-wide. Behind the LB this is intermittent misrouting (route works ~1/N of the time; peers serve the catch-all). **Confirmed root cause:** routes are the only config domain whose mutation skips the shared doc — `handle_route_upsert` does a bare local `RouteTable::apply` ArcSwap swap (`admin_mutate.rs:5518-5520`, `route/mod.rs:119-124`) instead of `load_active_config_doc → store.activate(…)` + nudge like pools (`:524`)/rules/tiers. So `config:waf:doc` version never bumps (stuck at 101 fleet-wide) and the route is non-durable across restart. The watcher already re-derives routes on a doc landing (`apply_cfg_change_to_routes`, `redis_source.rs:242`) — the write side just never feeds it. Fix: serialize routes into the doc + activate + nudge (mirror the pool path); add a per-node converge/drift indicator; regression-test 2-node convergence. |
| [`BUG-route-strip-prefix-toggle-not-roundtripped.md`](./BUG-route-strip-prefix-toggle-not-roundtripped.md) | BUG (dashboard ↔ API state) | 🟡 Medium | 🔴 **Open.** "Strip route prefix when forwarding" always re-opens **checked** even after the operator unchecks + saves. `GET /api/routes`'s `RouteSummary` (`api/routes.rs:41-70`) has no `strip_prefix` field, so `route_summaries` (`route/mod.rs:285`) drops it and the dashboard reads `r.strip_prefix !== false` = `undefined !== false` = `true` (`pages.jsx:13969`). Applied value is correct, but the stale-checked modal re-submits `strip_prefix: true` on the next edit, silently re-enabling stripping. Not the cause of the route→catch-all misroute (that's the convergence bug; `strip_prefix` only rewrites the forward path, not matching). Fix: add `strip_prefix` to `RouteSummary` (default `true`) + populate in `route_summaries`. |
| [`BUG-create-route-pool-not-found-race.md`](./BUG-create-route-pool-not-found-race.md) | BUG (UX / config-plane race) | 🟡 Medium | 🔴 **Open.** Creating a pool inline via **Add route → "+ Create new pool"** then immediately saving the route fails with `upstream "<pool>" not found`; succeeds on retry a few seconds later. Optimistic dropdown update (`handleChildPoolSave`, `pages.jsx:14074`) races the async config-plane apply — `validate_route` checks the per-node `current_pools()` shadow (`admin_mutate.rs:5450-5461`) which lags pool *activation* ("propagates … within a few seconds"). Standalone flows gate on `waitForVersion`; this child-pool path skips it. Fix: gate the route **Save** on `waitForVersion(before+1)` (or validate routes against the active config doc, not only the shadow). |
| [`WEBSOCKET_ATTACK_REPORT.md`](./WEBSOCKET_ATTACK_REPORT.md) | gap analysis | Medium | 🟡 WebSocket attack-surface gap report (4/29 blocked at time of writing). **Partially resolved:** RC-1 (`ws_inspect` ON by default, PR #40), RC-3 (cookie-injection detector, PR #42), and oversized-frame fail-closed + XFF/IP-spoof hardening (PR #41) all shipped. **Still open:** RC-2 (WS `Origin` allowlist / `ws_require_origin` — not in code), RC-5 (`Sec-WebSocket-Protocol` / WS-specific header scanning), and the RC-4 SSE cross-site (CORS/Origin) check. **2026-06-13 verification (§8):** RC-7 closed (mock + fast-upstream now echo WS same-port); `ws_inspect` confirmed blocking a `/ws/live` SQLi frame (1008, `tag=sqli`). Found **BUG-WS-1** (plaintext `:8080` never upgraded WS — missing `.with_upgrades()`; **fixed** in `accept.rs`), **BUG-WS-2** (AI detector over-blocks 100% of WS frames in enforce — OOD on per-frame views; **open**, left as-is, workaround `mode: log_only`), **BUG-WS-3** (plaintext bridge sends bare TCP close not the 1008 frame; minor). Re-scope the residual before picking it up. |
